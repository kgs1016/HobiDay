## Supabase

점검 시작 기준: SQL 파일 99개, 운영 이력 91개. 운영 함수 94개 중 현행 88개는
주석/공백을 제외한 본문과 security definer/search_path 설정이 로컬 전체 재구성 결과와 일치했다.

### 다음 일괄 배포 시 이력 정리 순서

이 절차는 이번 점검의 누락 8개에 한정한다. 새 변경이 들어오면 먼저 다시 비교한다.
구버전 파일을 그대로 `--include-all`로 실행하면 크레딧 함수가 되살아날 수 있다.

1. 최신 main·통합 변경을 확인하고 `supabase migration list`를 다시 읽는다.
2. `supabase db query --linked --file supabase/history-reconciliation-check.sql`
   — 88개가 모두 true여야 한다. 하나라도 달라졌다면 이력을 표시하기 전에 실제 변경을 재점검한다.
3. 누락 정리만 적용:
   `supabase db query --linked --file supabase/migrations/20260908220000_retire_remaining_workflows.sql`
4. `supabase/verify.sql` 및 `supabase/history-reconciliation-check.sql`을 읽기 전용 실행.
   현행 검사와 함수 비교가 전부 true인지 확인한다.
5. 실제 반영을 확인한 아래 버전만 적용 이력으로 기록한다.

```sh
supabase migration repair --linked --status applied \
  20260907140000 20260907160000 20260907180000 20260907200000 \
  20260907220000 20260908120000 20260908160000 20260908180000 \
  20260908220000
supabase migration list
supabase db push --dry-run
```

`history-reconciliation-check.sql`은 이력 테이블을 변경하지 않는 비교문이다.
`verify.sql`은 폐지된 조기 확정 대신 현재 2명 확정·차단 방향·공개 범위 등을 점검한다.
