# 운영 공지 작성자 표시 복구 — 2026-09-11

운영자 계정 삭제로 기존 공지 두 건의 `author_id`가 null이 되어 앱이 ‘탈퇴한 회원’으로 표시했다. 삭제 계정을 복원하지 않고 확인된 두 공지에만 운영팀 이름과 기존 profile-photos 로고 경로를 보존했다.

- 운영 반영: `20260911130000_official_notice_attribution.sql` 및 동일 버전 마이그레이션 이력.
- `post_detail`, `board_feed`, `post_list_by_category`의 기존 nickname/photo 응답 필드에 공식 작성자 대체 정보를 제공한다. 구형 `post_list`도 해당 목록 함수를 호출하므로 호환된다.
- 클라이언트는 posts 직접 쓰기 권한이 없으며 기존 작성/수정 RPC에서 공식 작성자 필드를 받지 않는다.
- 계정, 소유권, 본문, 작성일, 댓글, 차단 및 일반 탈퇴 사용자 표시는 변경하지 않는다.
- 운영 트랜잭션에서 변경 전 모든 게시글 원본 및 상세 응답을 임시 보존한 후 검증하고 롤백했다. 동일 검증을 실제 적용 트랜잭션에서도 수행했다.
- 두 공지만 운영팀 이름/로고를 반환하고, 관련 없는 모든 상세 응답과 기존 게시글 데이터가 일치함을 확인했다. 적용 후 별도 SELECT로 두 공지 응답, 이력 등록, 운영자 계정 미복원을 확인했다.
- DB 변경만 필요하다. 웹 빌드 및 네이티브 재빌드/스토어 재제출은 필요하지 않다. 화면 재진입 시 기존 앱이 새 응답을 읽는다. 실제 기기 UI는 사용자 확인 필요.

검증 SQL은 `supabase/tests/official_notice_attribution.sql`이다. 변경 전 같은 트랜잭션에 `notice_before(id, raw, detail)` 임시 테이블을 생성해 실행한다.
