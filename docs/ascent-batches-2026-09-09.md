# 완등 일괄 기록 — 배포 대기

## 기록 방식

`/me/ascents`에서 날짜와 암장을 입력하고 색상을 선택한다. 선택한 각 색상의 개수를 ± 버튼이나 숫자 입력으로 정한 뒤 한 번에 저장한다. 문제 이름이나 번호는 요구하지 않는다. 상단의 `단계 기준표 보러가기`와 색상표 링크는 입력한 날짜·색상·개수를 같은 계정/탭에 최대 한 시간 보관한다.

색상은 암장 난이도 라벨이다. [락타 공식 App Store 소개](https://apps.apple.com/kr/app/락타-rockta-클라이밍-캘린더/id6755939445)의 방문 암장·날짜·난이도별 횟수 기록 방식을 참고했다. 실제 락타 앱 내부의 기록 동작을 직접 실행한 것은 아니다.

메트로락은 V등급이 병기된 암장 안내표(이용자 재게시)를 바탕으로 자동 환산한다. 범위는 화면에 표시하고 하한을 성취에 반영한다. 원본 작성일/현재 현장 적용 여부는 미확인으로 표시하며 직접 입력으로 변경 가능하다. 다른 브랜드는 아직 V환산이 없다. V등급이 없는 기록은 총 완등에만 포함한다. 같은 색상 안에 서로 다른 V등급이 섞였으면 묶음을 나눠 입력한다. 개별 문제 ID를 입력하지 않으므로 같은 문제 재완등의 중복 여부는 사용자가 구분한다.

## 저장·이전 기록 호환

- 신규 마이그레이션: `20260909180000_ascent_batches.sql`, `20260909190000_verified_grade_mappings.sql`.
- `climbing_ascent_batches`: 사용자, 암장, 실제 완등일, 참고 브랜드, 저장 ID. 이전 기록을 변환할 때 원래 문제명을 `legacy_problem`에 보존.
- 기존 `climbing_ascents`에 색상·개수·묶음 ID를 추가. 기존 행은 개수 1, 원래 문제명 유지.
- 묶음 저장 RPC가 전체 입력을 먼저 검증한 다음 하나의 트랜잭션에서 교체. 색상당 1~99개, 최대 20색/500개. 미래 날짜·잘못된 V값·중복 색상은 거절.
- 요청 ID는 저장 재시도에 재사용하고 요청 전 임시 저장한다. 저장 성공 시 임시 값을 지운다. 수정은 총 개수를 교체하며 삭제 시 소속 행이 함께 삭제된다.
- 본인/공개 성취 RPC는 행 수 대신 개수 합계를 계산한다. 공개 범위는 기존 `profile_visible` 규칙 그대로다.
- 구버전의 개별 목록은 기존 행만 반환한다. 새 묶음을 구버전 요청으로 부분 수정하지 못하며 변환된 예전 ID의 재시도로 중복이 생기지 않는다.
- 신규 `climbing_ascent_history`는 묶음과 기존 기록을 함께 반환하고 저장 시각·ID 커서로 페이지를 나눈다. 기존 기록에 실제 완등일을 임의로 넣지 않는다.
- 개발 모드에서 Supabase가 없는 경우에만 메모리 미리보기 기록을 허용하고 화면에 운영 미반영을 표시한다. 페이지를 새로 불러오면 미리보기 내역은 사라질 수 있다.

이 일괄 기록 변경 뒤에 `20260909200000_shoe_stages_rolling.sql`을 적용하면 새 클라이언트는 최근 3개월·9색 단계를 사용한다. 구버전 7색·누적 RPC는 유지한다. [9색 정책](shoe-stages-2026-09-09.md) 참고.

## 검증

- 임시 PGlite DB에서 107개 마이그레이션 적용 및 `climbing_ascents.sql`, `public_climbing_achievements.sql`, `ascent_batches.sql`, `verified_grade_mappings.sql` 통과.
- 일괄 저장/편집/삭제, 중복 재시도, 잘못된 입력의 전체 취소, 다른 계정 격리, 공개 단계 집계, 이전 기록 변환/원문 보존, 구버전 재시도 차단, 커서 페이지, 계정 삭제 연쇄 처리 확인.
- 기존 공개 성취 테스트는 이미 도입된 `profile_visible` 정책에 맞춰 확정 모임 상대와 관계없는 비공개 상대를 별도 검증하도록 수정했다. 공개 정책 자체는 변경하지 않았다.
- 변경 파일 린트·TypeScript 및 브랜드/일괄 입력/임시 저장/암벽화 경계값 테스트 수행.
- 352px 브라우저 미리보기에서 노랑 3개·파랑 2개 선택, 기준표 왕복 후 복원, 5개 일괄 저장과 수정 폼 복원을 확인했다.

운영 DB 마이그레이션과 웹 배포는 사용자가 요청하는 일괄 배포 때 진행한다.

## 기타 입력·자동 환산

- 암장 입력 옆 `기타 암장 직접 입력`으로 목록에 없는 이름을 입력한다. 목록 입력 자체도 자유 입력을 허용한다.
- 알려진 브랜드에서도 색상 팔레트 끝의 `기타`로 빠진 색상 이름·개수·선택 V등급을 기록한다.
- 자동/직접 입력/모름을 한 묶음에 섞어 저장한다. 빈 색상과 중복 색상은 거절한다.
- 메트로락 6색만 자동 환산한다. V1–V2 → V1, V5+ → V5. 다른 암장으로 추정 전파하지 않는다.
- `grade_mapping_id`를 보존하고 DB 카탈로그에서 V값을 결정한다. 암장·색상·버전 불일치는 전체 요청을 거절한다.
- 카탈로그 수치와 출처는 버전별 불변이다. 변경 시 새 ID를 추가하고 기존 기록은 소급 환산하지 않는다.
- 기존 수동 V등급은 보존한다. 내역과 수정 폼에서도 자동/직접 입력을 구분한다.
- 암장 변경 시 자동 V를 다시 설정한다. 기타 이름·색상·모드·자동 출처도 기준표 왕복 시 복원한다.
