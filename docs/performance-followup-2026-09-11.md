# 아이폰 화면 전환 지연 점검 — 2026-09-11

보고: iPhone 15 Pro의 Safari 웹사이트에서 키보드를 사용하지 않아도 화면 전환이 느리거나 렉이 발생함. 앞선 보고에는 하단 메뉴가 위로 들리는 현상도 포함됨. 사용자는 설치 앱에서는 이 현상이 발생하지 않는다고 확인했다. Safari 현상의 추가 재현은 앱 업데이트 배포 뒤에 이어간다.

## 로컬 수정 · 미배포

- 홈에서 프로필 조회 후 모임/사람 조회를 시작하던 순차 대기를 제거했다. 인증 확인 후 메뉴와 필터를 표시하며, 프로필·사진은 따로 갱신한다.
- 모임과 사람 목록은 각각 응답하는 즉시 표시한다. 느린 사람 조회가 빠른 모임 조회의 표시를 지연시키지 않는다. 두 목록의 로딩 상태를 분리하고, 실패를 빈 목록으로 처리하지 않는다.
- 하단 메뉴 배지의 고정 간격 setInterval을 기존 startPolling으로 교체했다. 응답 완료 후 다음 조회를 예약하고 화면 이탈/백그라운드 전환 시 RPC를 취소한다. 홈 편지 배지에도 취소 신호를 전달한다. 배지 값이 같으면 상태를 갱신하지 않는다.
- 앞선 요청의 '처음 시작해요' 버튼 변경은 그대로 보존한다.

## 검사와 한계

변경 파일 린트, 전체 TypeScript 검사, 홈 목록·런타임·프로필 참여 회귀 검사 통과. 느린 사람 응답을 보류한 상태에서 모임 결과가 먼저 전달되고, 나중에 실패한 사람 응답은 오류로 구분되는 회귀 검사를 추가했다. 로컬 예시 데이터에서 홈→게시판 이동과 하단 링크 유지를 확인했다.

실제 iPhone 렉이나 하단 메뉴 들림을 재현하거나 수정 완료했다고 판단하지 않는다. 화면 고정 CSS나 네이티브 키보드 설정은 추측으로 변경하지 않았다. 실제 기기/실행 방식 확인 후 화면 위치, 스크롤, 요청 지연을 따로 측정해야 한다. 서버 사양·운영 DB는 변경하지 않았고 빌드·배포·네이티브 동기화를 수행하지 않았다.
