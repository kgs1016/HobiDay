# 프로필 작성 이용 현황 — 2026-09-16

상태: 로컬 구현. 운영 DB·웹·설치 앱에는 아직 반영하지 않았다.

## 수집 범위

일반 회원의 기본정보/클라이밍화 화면, 입력 조건, 저장 후 이동 경로는 그대로다.
프로필 화면 진입·불러오기 완료·저장 시도·저장 완료·입력 확인·실패를 기록한다.
클라이밍화는 가입 단계와 내 프로필의 **첫 설정** 창을 포함한다. 초기화는 제외한다.
기본정보 화면 기록에는 신규 작성과 기존 정보 수정이 모두 포함된다.

- 내부 회원 ID는 서버 `auth.uid()`로 결정한다. 클라이언트가 다른 회원 ID를 지정할 수 없다.
- 저장 항목은 이벤트 종류, 서버 시각, 웹/iOS/Android, 설치 앱 버전, 제한된 오류 유형이다.
- 입력 중인 이름·성별·구력·사진·메일·본문·URL·오류 원문은 수집하지 않는다.
- 기록 전송을 기다리거나 자동 재시도하지 않는다. 요청은 최대 2.5초, 대기 이벤트는 최대 20개다.
- 세 번 연속 전송 실패 시 1분 중단한다. 서버는 계정당 시간당 60건으로 제한한다.
- 새 SDK나 제3자 분석 서비스 없이 기존 Supabase RPC를 사용한다.
- 개발 서버는 기본적으로 기록하지 않는다. 로컬 검증에만 `NEXT_PUBLIC_PROFILE_USAGE_ENABLED=true`를 사용할 수 있다.
- 운영 빌드는 기본 활성화한다. `NEXT_PUBLIC_PROFILE_USAGE_ENABLED=false`로 빌드하면 수집을 끌 수 있다.

## 운영자 조회

로그인한 운영자가 `/admin/usage`로 접근한다. 일반 메뉴에 링크를 추가하지 않았다.
`public.app_admins`에 등록된 계정만 서버 `is_app_admin()` 판정을 통과한다.
이번 작업으로 운영자 권한을 새로 부여하거나 계정을 만들지는 않았다.

오늘/7/14/30/90일을 한국 날짜 기준으로 조회하며 기본값은 최근 7일 신규 가입자다.
‘기간 내 신규 가입자만’을 해제하면 해당 기간 기록이 있는 기존 회원도 포함한다.
단계별 수치는 해당 이벤트가 관측된 고유 계정 수다. 여러 단계에 같은 사람이 포함된다.
**순서대로 진행한 전환율이나 체류 시간 측정은 아니다.** 최근 계정별 요약은 최대 100명이다.
로그아웃·계정 변경 시 이전 보고서와 늦게 도착한 응답을 폐기한다.

아직 기록이 없는 신규 가입자도 표시하지만, 구버전·통신 실패·배포 이전 진입 등은
‘앱 미사용’으로 판단하지 않는다. 과거 화면 진입은 복구할 수 없다.
사진 업로드 실패 등 마지막 오류 유형은 분류값만 표시한다.

## DB와 배포 순서

새 마이그레이션: `supabase/migrations/20260916160000_profile_usage.sql`.

1. 일괄 배포 시 운영 이력의 마지막 버전과 대기 SQL을 확인한다.
2. 개인정보처리방침의 추가 수집 안내와 기존 고지·시행 일정을 맞추고, 스토어의 데이터 수집 안내도 실제 항목과 맞춘다.
3. 새 SQL을 먼저 적용한다. 이미 적용한 과거 SQL은 재실행하지 않는다.
4. 기존 운영자 계정으로 조회 권한을 확인한다. 권한이 없다면 계정을 확인한 뒤 별도 지정한다.
5. 웹 배포 후 웹 진입부터 수집을 확인한다. 설치 앱은 이 코드가 포함된 Codemagic 빌드 배포 이후부터 수집한다.

테이블 직접 접근은 anon/authenticated 모두 불가하다. 일반 회원은 본인의 제한된 이벤트
저장 RPC만 사용할 수 있고 조회 RPC는 서버에서 운영자 여부를 확인한다.
90일이 지난 기록은 pg_cron의 `profile-usage-retention` 작업이 매일 04:00 UTC에 삭제한다.
계정 삭제 시 FK cascade로 함께 삭제된다. cron이 없는 테스트 DB에서는 정리 함수를 직접 호출한다.
운영 적용 때 cron 등록도 함께 확인해야 한다.

## 검증

린트·타입 검사와 전체 17개 기능 검사 스크립트, 격리 SQL 검사를 통과했다.
DB 연결을 끈 개발 서버에서도 `/admin/usage`의 제목·기간 필터·연결 오류 표시를
브라우저에서 확인했다. 실제 운영자 계정과 운영 DB를 연결한 수신 확인은 배포 후 진행한다.

- `web`에서 `npm run check`: 린트·타입·기능 회귀 검사.
- `web/scripts/test-profile-usage.cjs`: 전송 실패/타임아웃, 계정별 인증 토큰 고정,
  Strict Mode 중복 진입, 개발 환경 제외, 허용 필드, 운영자 화면 로그아웃/응답 경합 검사.
- `web/scripts/test-profile-onboarding.cjs`: 저장 성공/실패·재시도와 기존 이동 경로 검사.
- `supabase/tests/run-profile-usage-test.cjs`: 격리 PGlite에서 본인 기록·운영자 권한,
  중복 제거·집계·요청 제한·보관기간·탈퇴 삭제 검사.
  실행 환경에 `@electric-sql/pglite`가 필요하며 운영 DB를 사용하지 않는다.
