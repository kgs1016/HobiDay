**하비데이 안정성 복구 — 로컬 적용, 배포 대기**

9월 12일 분석에서 확인한 요청 미응답, 채팅 실패 처리, 영상 업로드 복구와 구버전 API 호환 문제를 수정했다. 기준 main은 `51d4c2d`이며 수정 브랜치는 `codex/stability-recovery-20260914`다. 앞선 분석 자료는 `ff68ce9`에 별도로 보존했다.

**변경된 동작**

- 1:1·모임 채팅 목록이 각각 도착하는 대로 표시된다. 한쪽 오류가 다른 쪽을 가리지 않는다. 초기 실패·빈 목록·기존 목록 갱신 실패를 구분하고 재시도를 제공한다.
- 대화 내용의 초기 조회 실패에도 재시도 버튼을 표시한다. 이미 받은 대화는 유지한다.
- 전송 실패 시 메시지를 지우지 않고 전송 버튼을 다시 활성화한다. 성공 때만 입력을 지우고 동시 중복 제출을 막는다. 서버에 저장됐으나 응답만 사라진 경우를 고려해 전송 결과 확인을 안내하며, 쓰기를 자동 재전송하지 않는다.
- Supabase REST/auth 요청에 대기 제한을 추가했다. 채팅 목록·메시지·전송·영상 게시 요청은 응답 처리 전체에도 제한을 둔다. 폴링은 취소를 무시하는 요청이 있어도 18초 뒤 해제되고 화면 복귀·온라인 복귀 시 재연결한다.
- 홈·채팅·참여 확인은 일시적인 인증 통신 실패와 실제로 무효한 세션을 구분한다. 하단 메뉴는 일시적인 인증 실패 때문에 기존 메뉴를 숨기지 않는다. 기존 nullable 인증 호출 계약은 유지한다.
- 홈과 하단 메뉴의 배지 요청을 사용자별로 공유하고 2초간 결과를 재사용한다. 계정 변경과 비로그인에서는 이전 결과를 사용하지 않는다.
- 영상 및 교체 파일 업로드는 TUS를 사용한다. 6MiB 조각, 제한된 자동 재시도, 저장된 업로드 위치 재개, 진행률, 일시 중지를 제공한다. 운영 Supabase URL은 직접 Storage 호스트를 사용하며 인증 토큰은 매 요청 시 확인한다.
- 영상 전송이 완료됐으면 썸네일 실패 때문에 다시 전송하지 않는다. 게시된 기존 파일을 덮어쓰거나 실패 시 삭제하지 않는다. 새 영상 선택 단계의 자동 썸네일 생성에 실패해도 별도 사진을 골라 진행할 수 있다.
- 새 영상은 계정별로 파일·썸네일·설명·업로드 단계가 IndexedDB에 저장된다. 새로고침·화면 재진입 때 복원하며 유효기간은 24시간이다. 큰 미디어와 설명/진행 정보는 별도 레코드에 저장해 글자 입력마다 파일 전체를 복사하지 않는다. 저장 공간을 사용할 수 없으면 해당 화면에서 완료하도록 안내한다. 게시 성공 후 초안을 삭제하고, 성공 직후 재저장되는 경합도 막는다.
- 교체 영상은 같은 화면 안에서 부분 업로드를 재사용한다. **편집 화면의 파일 선택을 앱 재시작 뒤까지 복원하는 기능은 이번 범위에 포함하지 않았다.**

**운영 적용이 필요한 항목**

`20260914090000_legacy_read_compatibility.sql`은 아직 운영에 적용하지 않았다. 구버전의 `my_credits`, `my_videos`, `my_confirm_proposals` 읽기 호출에 예전 형식의 비어 있는 응답을 반환한다. 크레딧 원장·적립·차감·폐지된 모임 미션은 복원하지 않는다. 현재 영상은 기존 `my_video_posts`를 계속 사용하고, 예전 미션 영상 목록에는 노출하지 않는다. 세 함수는 authenticated 역할만 실행할 수 있는 security invoker 함수다.

이 호환 응답은 구버전의 불필요한 404를 줄이는 조치다. 구버전에 새 기능이나 새 화면을 전달하는 조치는 아니다. 웹과 DB는 다음 일괄 배포에 반영하고, 설치 앱은 Codemagic에서 새 번들로 업데이트해야 한다. 스토어 공개 전 최신/최소 지원 버전 정책을 임의로 올리지 않는다.

**검증**

- 전체 린트·TypeScript·기존 기능 테스트와 새 안정성 회귀 테스트.
- 실제 채팅 전송 콜백에서 실패 시 입력 보존, 버튼 해제, 중복 제출 방지, 성공 후 입력 삭제.
- 요청 미응답·취소·화면 복귀, 목록별 독립 성공/실패, 배지 중복 요청·계정 격리, 인증 실패 후 복구.
- 격리 PGlite에서 호환 SQL 반복 적용, 반환 형태, 실행 권한, 폐지 테이블/특권 기능이 생기지 않음을 확인.
- IndexedDB 검증에서 파일 복원, 설명 갱신 시 업로드 단계 유지, 계정 격리, 초안 삭제.
- Chrome 390×844 모바일 화면에서 API 응답을 전부 테스트용으로 대체하여 9개 사용자 흐름을 검증했다. 실제 TUS 클라이언트로 6MiB 초과 파일의 중간 PATCH를 실패시켰고 HEAD로 이전 위치를 확인한 뒤 이어 전송했다. 영상 POST 1회, 썸네일 POST 2회로 썸네일 실패·새로고침·재시도·게시 완료까지 확인했다.

이번 검증은 운영 사용자 데이터를 만들거나 실제 휴대폰으로 업로드한 검사가 아니다. iOS/Android 기기의 백그라운드 중단, 실제 LTE/Wi-Fi 전환, MOV/HEVC 파일, 실제 Supabase TUS 경로의 최종 수신은 앱 업데이트 준비 시 실기기로 확인해야 한다. 브라우저 TUS만으로 앱 종료 뒤 백그라운드 전송까지 보장하지 않는다.

**재현 명령**

웹 폴더에서 `npm run check`를 실행한다. 별도 도구 경로를 `NODE_PATH`로 지정해 아래 검사를 실행할 수 있다. 별도 도구는 제품 의존성에 추가하지 않았다.

```sh
NODE_PATH=/path/to/tools/node_modules node supabase/tests/run-legacy-compatibility-test.cjs
NODE_PATH=/path/to/tools/node_modules node web/scripts/check-video-draft-storage.cjs
```

필요 도구는 각각 `@electric-sql/pglite`, `fake-indexeddb`다. 브라우저 검사는 `@playwright/test`와 설치된 Google Chrome을 사용한다. 테스트 서버는 아래처럼 실행하고 별도 터미널에서 스크립트를 실행한다. 실제 운영 계정이나 토큰은 필요 없다.

```sh
cd web
NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321 NEXT_PUBLIC_SUPABASE_ANON_KEY=stability-test-key npm run dev -- --hostname 127.0.0.1 --port 3021
# 다른 터미널, 저장소 루트
NODE_PATH=/path/to/tools/node_modules node web/scripts/check-stability-browser.cjs
```

테스트 서버를 종료한 뒤 일반 개발 서버를 다시 실행해야 테스트 전용 환경 값이 남지 않는다. 웹 배포 빌드·네이티브 동기화·운영 마이그레이션은 이번 로컬 단계에서 실행하지 않았다.

남은 개선 후보는 실시간 채팅 구독/메시지 페이지 조회, 사용자 경로별 원격 성능 계측, 외부 글꼴 의존 제거, 홈 목록 캐시다. 이번 수정과 별개로 실제 기기 수치를 확인해 우선순위를 정한다.
