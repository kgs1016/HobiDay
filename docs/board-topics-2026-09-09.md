# 자유게시판 주제·검색·고정 안내

운영팀의 기존 글 2건을 작은 공지 영역으로 분리하고, 그 아래에서 일반 글을 주제별로 읽도록 구성했다. 고정은 화면에 계속 떠 있는 sticky 방식이 아니라 목록 최상단 배치다.

- 고정 순서 1: `be301249-1702-4ff8-8956-998078cb443c` — 자유게시판, 이렇게 함께 써요 👋
- 고정 순서 2: `3bda1726-ae43-4289-be9a-ea7460334aa9` — 하비데이에 이런 기능 있으면 좋겠어요! 💡
- 주제: 전체 / 일상 / 질문 / 암장 후기 / 분실물. 기존 글은 일상으로 보존한다.
- 공지는 주제·검색과 무관하게 상단에 유지하고 일반 목록에서 제외한다. 차단·삭제된 글은 공지라도 표시하지 않는다.
- 검색 아이콘을 누르면 입력창을 펼친다. 제목과 **전체 본문**을 함께 검색하며 선택한 주제와 결합한다. 검색은 제출할 때 적용하고 최대 80자다.
- 검색어와 주제는 URL에 보관해 상세에서 뒤로 돌아왔을 때 복원한다. 선택한 주제에서 글쓰기를 열면 해당 주제가 기본으로 선택된다.
- 게시글 목록과 상세에 주제를 표시하고, 글 작성·수정에 주제 선택을 추가한다. 장비 추천과 영상은 이 주제 필터에 포함하지 않는다.

[당근의 동네생활 주제 운영 사례](https://about.daangn.com/company/pr/archive/당근마켓-2021년동네생활게시글1위는동네질문/)를 참고하되, 홈의 모임과 별도 장비 추천 게시판에 겹치는 분류는 만들지 않았다. 현재 사용자 규모를 고려해 주제 4개만 시작한다.

## 데이터와 배포

신규 SQL은 `supabase/migrations/20260909234500_board_topics_and_pins.sql`이다. 2026-09-09 운영에서 `233000` 뉴스 입력 한도, 이 `234500` 변경, `supabase/content/20260909_news_and_gear.sql`을 한 트랜잭션으로 적용했다. 최신 이력은 `20260909234500`, 총 113개다.

`board_feed`는 고정 목록과 일반 글 한 페이지를 분리해 반환하며, 생성 시각+ID 커서로 페이지를 넘긴다. 새 `post_create_with_topic` / `post_update_with_topic`은 기존 인증·도배 방지·소유자 검사 함수를 사용한다. 기존 RPC는 유지하므로 예전 앱에서 수정해도 주제가 사라지지 않는다. 고정 순서는 일반 작성·수정 RPC로 받지 않는다. 운영에서 확인한 글 ID와 작성자 ID가 일치하는 두 글만 고정한다.

운영 DB에서 공지 2건의 순서, 원래 본문·댓글 보존을 확인했다. 일반 목록 중복 제외와 권한·검색·페이지 넘김은 로컬 SQL 실행으로 검증했다. 예전 설치 앱은 기존 시간순 목록을 유지하며 새 UI는 새 번들부터 적용된다.

검증: 변경 파일 린트·타입 검사, `web/scripts/test-board-topics.cjs`, `supabase/tests/board_topics.sql`, 기존 게시판·뉴스 회귀 검사. SQL은 로컬 PGlite에서 전체 마이그레이션과 함께 실행했다. 운영 글 내용은 로컬 미리보기용 JSON에 복사했으며 테스트 사용자 글은 운영에 작성하지 않았다.
