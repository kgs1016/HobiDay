# 방문 빈도와 시작 암벽화 — 로컬 변경

운영 미적용. 웹 빌드·네이티브 동기화·푸시·SQL 적용은 다음 일괄 배포 때 진행한다.

## 방문 빈도

- 프로필 수정의 선택 항목. 최근 한 달을 기준으로 가끔 / 주 1회 / 주 2~3회 / 주 4회 이상 중 선택한다. 선택한 버튼을 다시 누르면 해제한다.
- `profiles.visit_frequency`는 nullable smallint(1~4). 기존 회원은 null로 유지한다.
- 사람 찾기는 빈도 + 작은 암벽화, 상세 프로필은 방문 빈도와 기존 구력을 각각 보여준다. 내 프로필의 이름 아래에도 선택한 빈도를 표시한다.
- 사진·기본 정보·공개 동의·모임 참여 필수 조건은 그대로다. 구력을 빈도로 자동 변환하거나 두 값을 같은 것으로 취급하지 않는다.
- 후속 UI: 구력 ID 1의 표시를 ‘6개월 미만’으로 바꾸고, 사람 찾기 공개 스위치를 한마디 입력 아래·저장 버튼 위로 옮겼다. 프로필 등록/수정에 함께 적용한다.

## 가입 흐름

- 기본 정보 입력(1/2) → 저장 성공 → 시작 암벽화(`/profile/shoe`, 2/2) → 내 프로필(`/me`). 아직 기본 정보가 완성되지 않은 기존 회원도 포함한다. 완성된 프로필 수정은 기존처럼 공개 여부에 따라 사람 목록/내 프로필로 이동한다.
- 큰 암벽화 그림과 9색 버튼, 선택 색의 H난이도·완등 수·점수 유지 기준을 표시한다. 전체 기준표는 별도 링크다. 기본 정보는 이미 저장되어 있어 다음 단계에서 나가도 보존된다.
- 저장 실패 시 해당 단계에 머물러 재시도할 수 있다. 저장 중 중복 클릭을 막는다. 암벽화 조회 실패는 재시도/나중에 설정을 제공한다.
- 나중에 설정은 색 선택 기록을 쓰지 않고 내 프로필로 이동한다. 이미 시작 색을 선택한 계정은 두 번째 단계 URL을 다시 방문해도 내 프로필로 이동한다.
- 기존 내 프로필의 설정 창과 가입 단계는 같은 StartingShoePicker를 사용한다. 기본 정보 필수 게이트를 유지하고 LaunchGate에는 새 경로를 허용한다. 새 정적 페이지라 동적 ID 라우트를 만들지 않는다.

## 첫 시작 색

- 경로: 내 프로필(`/me`) → 내 암벽화 → 시작 암벽화 설정.
- 기존 회원 포함, 해당 계정의 시작 설정 이력이 없으면 한 번 9색 중 선택할 수 있다. 색을 고르기 전 저장은 불가하며 취소할 수 있다.
- 선택일의 한국 날짜 + 3개월(말일 보정)이 만료일이다. 만료일 전에는 시작 색/실제 기록 단계 중 높은 단계를 표시하고, 만료일부터 실제 기록만 적용한다.
- 점수와 완등 수를 만들거나 기존 기록을 초기화하지 않는다. 임시 시작 색이 실제 기록보다 높을 때만 `시작 설정`을 표시한다.
- 본인은 현재 시작 색을 실제 기록으로 유지하는 데 필요한 점수·최소 H난이도 완등 수와 전환일을 본다. 기록이 시작 단계에 도달하면 일반 다음 단계 진행률로 돌아간다.
- `climbing_shoe_starts`는 auth.users에 연결한다. 일반 프로필 upsert로 바꿀 수 없으며, 프로필만 지웠다가 다시 만들어도 리셋되지 않는다. 계정 탈퇴 시 cascade 삭제된다.
- 고유 user_id와 INSERT ON CONFLICT로 1회 제한. 같은 색 재시도는 저장일/만료일을 변경하지 않고 결과만 반환한다. 다른 색은 만료 후에도 거절한다.
- 본인은 자기 시작 정보만 읽을 수 있다. 다른 회원에게는 기존 `profile_visible` 확인 후 색·누적 완등·표시 근거(starting/records)만 공개한다.

## 반영 순서와 호환

1. 운영 migration list/스키마를 확인하고 신규 `20260910050000_profile_frequency_and_shoe_start.sql`을 적용한다.
2. 새 컬럼과 `climbing_shoe_start_set`, `climbing_progress_v5`, `public_climbing_achievements_v5`, `user_profile_v2` 및 권한을 확인한다.
3. 웹/네이티브 번들을 함께 검증한다. 기존 v4 성취·user_profile RPC는 수정하지 않아 설치된 이전 앱에서 원래 기록 기준이 유지된다. 이전 앱에 새 선택 화면/시작 색을 보여주려면 앱 업데이트가 필요하다.

## 검증

- 변경 파일 린트·TypeScript 검사 통과. 로컬 화면에서 시작 버튼·9색 선택·저장 후 점수 0 유지·설정 버튼 제거를 확인했다. 후속 가입 점검에서는 기존 사진 없는 미리보기 프로필에 저장소의 테스트 이미지를 입력하고 방문 빈도를 선택한 뒤, 기본 정보 저장 → 암벽화 단계 → 나중에 설정 → 내 프로필에서 빈도/설정 기회 유지를 확인했다. 이후 암벽화 단계에서 핑크를 선택해 H7/20개/720점 안내와 최종 내 프로필의 핑크·시작 설정·0점/0개 표시를 확인했다. 운영 계정이나 사진을 변경한 검사가 아니다.
- 프런트 기능 검사: 시작 색의 기간 경계·말일·기록 우선·점수/개수 불변·실제 기록 전환·공개 source 파싱, 방문 빈도 저장/재조회/해제·기존 회원 null·기존 필수 조건 유지.
- 기존 브랜드/색상/묶음 기록 회귀 검사.
- `test-profile-onboarding.cjs`: 기본 정보의 저장 성공/실패·중복 요청·공개/비공개 보존·신규 단계/기존 수정 분기, 암벽화 단계 로그인·재선택 제한·조회 재시도, 건너뛰기 시 저장 없음·선택 유지 후 재시도 확인. 전체 npm test에도 포함한다.
- 격리 PGlite: 실제 최신 색상 카탈로그/집계/프로필 가시성 함수와 신규 SQL을 함께 실행. 1회 제한/동일 요청 재시도/만료 후 재설정 금지, 권한/비공개/차단, 기존 RPC 호환, 실제 H8→H11 성취 우선, 프로필 재생성 및 계정 삭제 생명주기를 확인한다. 관련 없는 session_member 분기만 빈 결과로 대체한 테스트 환경이며 운영 계정을 수정하지 않는다.
- 실행: `NODE_PATH=<@electric-sql/pglite가 설치된 modules> node supabase/tests/run-profile-start-test.cjs`.
- 로컬 브라우저는 Supabase 없는 개발 시안. 시작 선택과 완등 기록은 메모리 데이터이며 새로고침하면 초기화된다. 운영 저장 검증과 구분한다.
