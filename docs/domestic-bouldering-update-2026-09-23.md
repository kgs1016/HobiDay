## 반영 파일과 호환성

- [편집 원본](../supabase/content/20260923_domestic_bouldering.json): 공식 안내를 요약한 대회 정보와 한국어 자체 브리핑. `published_at`은 하비데이 편집 발행일이며 원문 게시일을 뜻하지 않는다. 뉴스 출처에도 하비데이 브리핑임을 표시한다.
- [콘텐츠 SQL](../supabase/content/20260923_domestic_bouldering.sql): 기존 `community_articles`에 10건을 넣는 재현용 단일 트랜잭션. 재실행 시 `external_id`로 중복을 막고 기존 ID·숨김·사진·최초 발행일을 보존한다. 같은 분류/출처 URL로 다른 키가 이미 등록됐다면 중단하므로 운영 적용 전 중복 대회를 확인하고 키를 맞춘다.
- 사진은 이번에 추가하지 않는다. 앱의 기존 목록·상세 API가 제목·본문·일정·출처를 서버에서 조회하므로 **콘텐츠만 반영할 때 앱 버전 변경이나 스토어 제출은 필요 없다**. 앱을 완전히 종료 후 다시 열면 새로 조회한다. 열어 둔 대회 목록은 메모리 캐시가 있어 즉시 바뀌지 않을 수 있다.
- JSON의 고유 키·제목/본문 길이·HTTPS 출처·일정 순서·대회 3건/뉴스 7건과 SQL 내 payload 일치를 검사했다. 운영 반영은 Supabase REST 단일 배치 upsert로 수행했다(SQL 파일 자체를 실행한 것은 아님). 반영 뒤 전체 21건을 재조회해 대상 10건의 본문·일정 일치, 신규 9건, 군산의 기존 ID·사진·숨김·최초 발행일 보존, 무관한 기존 11건 불변을 확인했다. 공개 상태의 예정 대회는 4건, 뉴스는 13건이다. 로그인한 실제 앱 화면 검증은 수행하지 않았다. 앱 코드와 스키마 변경이 없어 웹/네이티브 빌드는 실행하지 않았다.

## 자동 수집 점검

`.github/workflows/community-feed.yml`은 6시간마다 실행되도록 설정돼 있으나 최근 3회가 실패했다. [2026-09-23 06:28 KST 실행](https://github.com/kgs1016/HobiDay/actions/runs/35786892934) 로그에서 `SUPABASE_SERVICE_ROLE_KEY`가 비어 있어 수집 전에 종료된 것을 확인했다.

기존 수집기는 국제 일정과 광범위한 클라이밍 RSS를 가져온다. 따라서 키만 등록하면 국내 볼더링 기준과 다른 콘텐츠도 다시 유입된다. 이번에는 키 등록이나 워크플로 실행을 하지 않았다. 국내 볼더링만 자동 수집하려면 출처와 종목·개최국 판별을 별도로 수정해야 한다. 이번 수동 콘텐츠 갱신과 자동 수집 복구를 혼동하지 않는다.

이번에는 사용자의 대회 소식 업데이트 요청 범위에서 콘텐츠만 일괄 반영했다. 운영 중복 조회 결과 군산 대회가 이미 있어 기존 `curated:worldclimbing:asia-gunsan-2026` 키로 맞췄다. 스키마·마이그레이션·앱 배포·자동 수집 설정은 변경하지 않았다. 이후 재실행 전에는 공지 변경, 접수 상태, 기존 데이터 중복을 다시 확인한다.
